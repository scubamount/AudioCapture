# Audio Capture 2.1.0-dev.3 for Windows

Live transcription and completed-file batches now share one configuration. You can inspect recording and transcription settings while both activities run.

## Install and configure

1. Download and extract `AudioCapture-Rust-Windows-x64.zip`.
2. Copy `config/transcription.example.json` to `transcription.json` beside `audio-capture.exe`.
3. Set the endpoint, model, transcript folder, and timestamp preference for your service.
4. If the service needs a key, put its environment variable name in `api_key_env`. Keep the key in that variable.
5. Open `audio-capture.exe`. Select **Transcribe files…** for saved recordings or **Start transcription** for a live session.

Use **Transcription settings → Load config…** to switch profiles. Both workflows show the destination and ask for approval before sending audio.

## Changes since 2.0.0

- Start and stop recording and live transcription independently. The worker saves partial text during a call and publishes the final transcript on stop.
- Reuse the current transcription settings for a batch. The standalone guided worker reads `transcription.json` beside its executable.
- Open either settings panel during capture. The window scrolls to the settings and keeps active fields locked.
- Select recently used programs and manage queued batches from the recorder.

This is a prerelease. The two-hour recorder endurance check is open. Live speaker labels and recognition speech gating remain evaluation features. See the [operator guide](https://github.com/scubamount/AudioCapture/blob/v2.1.0-dev.3/rust/README.md) and [qualification results](https://github.com/scubamount/AudioCapture/blob/v2.1.0-dev.3/docs/benchmarks/live-performance.md).

To verify the ZIP, compare the output of `Get-FileHash .\AudioCapture-Rust-Windows-x64.zip -Algorithm SHA256` with `SHA256SUMS.txt` from this release.
